# Local editor contract · 1.0

This is the 1.0 source/API contract: four picture and four audio lanes, shared realtime/export DSP, volume automation, 18 transitions and 14 animation types. Native release evidence is recorded separately in V10-RELEASE-VALIDATION.md. Previous0.9 results below are historical, not proof of1.0. Jianying draft import is a documented requirement, not an implemented format: see JIANYING-DRAFT-COMPATIBILITY-REQUIREMENTS.md.

Historical 0.8 passed 101/101 source checks, the installed native import/drag/audio/edit/save/Finder-reopen/export flow and a separately scoped 2322/2322 MP4/WAV oracle. [0.8 release](V08-RELEASE-VALIDATION.md) and [native actions](V08-GUI-ACCEPTANCE.md) bind that older artifact and its limits. The 0.7 90/90 and 1642/1642 results and older 0.6 records remain historical evidence, not proof of the 0.9 release.

Project: `{id,version:1,name,width,height,fps,media:Media[],clips:Clip[],subtitles:Subtitle[],audioLanes:[{muted,solo},…4],createdAt,updatedAt}`.

Media: `{id,name,type:'video'|'audio'|'image',url,thumbnailUrl,duration,width,height,hasAudio,size}`. Server stores authoritative media records and files; imported projects reference local media IDs. Image default duration: 5 seconds.

Clip: `{id,mediaId,track:'video'|'audio',start,sourceStart,duration,speed,speedSegments,speedCurve,volume,muted,audioDetached,audioGainKeys,pan,audioEffects,layer,transform,transformKeys,adjustments,fadeIn,fadeOut,fadeInCurve,fadeOutCurve,animation,mask,transitionOut}`. Times are seconds; start is absolute timeline time and duration is timeline duration. Ordinary source consumption is duration×speed; segmented and smooth-curve timing are defined below. Image clips belong to video. Defaults speed=1, speedSegments=[], speedCurve=null, transformKeys=[], audioGainKeys=[], pan=0, volume=1, muted=false, audioDetached=false, layer=0, fadeIn=0, fadeOut=0, fadeInCurve=fadeOutCurve=linear. Versions 0.3–0.9 add fields/effect IDs within project version 1. GET validates older projects and supplies omitted defaults in its response without rewriting their stored JSON. Real edits and explicit saves persist validated fields; a new empty project or new demo copy is unsaved and does autosave. Loading or switching an unchanged saved project does not. Pending queued writes retain their identity so an Undo can save the restored snapshot after an older write completes. Focusing/blurring an untouched rounded numeric display does not change its exact stored value. 0.8 cannot preserve 0.9 lane routing, volume keys, balance/effects or new effect IDs; 0.7 cannot preserve new 0.8 audio semantics or effect IDs; 0.6 cannot preserve the new 0.7 animation/transition types; 0.5 cannot preserve speed curves or easeIn/easeOut; 0.4 also cannot preserve 0.5 keyframes, segmented speed or new animation/transition types. Back up the full library before using an older application.

- `speedSegments`: optional `[{sourceDuration,speed}]`, each sourceDuration 0.000001–3600 source seconds and speed .25–4. A nonempty array requires clip.speed=1 and duration=Σ(sourceDuration/speed) (validation tolerance .000001s); images cannot use it. Empty/omitted means ordinary duration×speed. These are piecewise constant rates with abrupt changes, not a continuous curve. Audio uses pitch-preserving time stretch for each span. Each ordinary clip counts as one decode input; each segmented span counts as one, with `MAX_DECODE_INPUTS=64` across the project.
- `speedCurve`: optional `{sourceDuration,points:[{id,position,speed,phase:[0,1]}]}`. It is mutually exclusive with nonempty speedSegments and requires clip.speed=1; images cannot use it. sourceDuration is the retained source span, .000001–3600 seconds. At least two unique-ID nodes are required, strictly increasing by at least .000001 normalized source position; the first/last positions are exactly 0/1 and cannot be moved or removed. Speed is .25–4. Adjacent rates interpolate continuously with smoothstep in the source domain; duration is `sourceDuration × ∫₀¹ 1/rate(position) dposition`. Owner-only phase preserves the relevant subcurve after trim/split; consumers do not reinterpret it. `clipSpeedCurve`, `speedCurveSamples`, `speedCurvePointBounds`, `createSpeedCurve`, `updateSpeedCurvePoint`, `addSpeedCurvePoint` and `removeSpeedCurvePoint` own normalization and edits. Presets smooth/rampUp/rampDown/montage are independent editor definitions, not Jianying assets. Project-wide `MAX_SPEED_CURVE_POINTS=128` is independent of the 128 transform-key limit. A curve clip uses one decode input, irrespective of node count. The UI preserves the source span when changing nodes, commits one pointer gesture as one undo action, and retains the latest valid draft when an owner edit rejects a pointer position.
- `layer`: integer 0–3 within the selected track kind: four picture lanes and four independent audio lanes, default 0 for both. Larger picture values render above smaller ones; same-picture-lane overlap is rejected and missing picture intervals show black. Audio overlap remains legal, including multiple clips in the same audio lane. `src/audio-lane-layout.mjs` owns deterministic visual subrow packing and header/container heights; this display layout never changes clip identity, time, duration or stored layer. Selecting a subrow scrolls that row into view.
- `project.audioLanes`: exactly four `{muted:boolean,solo:boolean}` entries; omission defaults all to false, explicit malformed arrays/values reject. Lane mute wins over solo. If any lane is solo, only unmuted solo lanes emit audio, and video-embedded original sound is excluded; without solo, lane mute affects only its audio lane. `clipAudioAudibility(clip,media,project)` owns `{enabled,reason,lane}` with reasons null/no-audio/clip-muted/detached/lane-muted/solo-excluded. Realtime playback, WAV and MP4 use the same routing facts.
- `transform`: `{scale:1,x:0,y:0,rotation:0,opacity:1,flipX:false,flipY:false}`. Scale is a 0.1–4 multiplier; x/y are project pixels relative to the centered fitted picture, positive right/down, bounded by twice the project width/height in each direction. Rotation is clockwise degrees, -360–360. Opacity is 0–1; flips are booleans. Source picture is fitted to the project canvas with transparent letterboxing; source flips and uniform scale run before rotation, then translation. Composition is clipped to the project canvas.
- `transformKeys`: optional `[{id,time,values:{scale,x,y,rotation,opacity},easing:'linear'|'easeInOut'|'easeIn'|'easeOut',phase:[0,1]}]`. Video/image only; time is clip-local seconds in [0,duration], strictly increasing with at least .000001s separation, and IDs are unique within the clip. Each values object is a complete five-property snapshot, using the same bounds as transform; flips remain static. There are at most `MAX_TRANSFORM_KEYS=128` across the project. Before the first key and after the last, hold the endpoint. Each key's easing governs interpolation to the next: linear u, easeInOut 3u²−2u³, easeIn u², easeOut 1−(1−u)². Rotation interpolates literal degrees (0→360 is one full turn). Owner-only phase retains a clipped easing interval; the UI does not edit it. `transformAt` owns sampled pose, `transformKeyProgressAt` supplies the interpolation graph, and upsert/remove/easing/navigation helpers return parsed keys or new clips. The selected list item and timeline diamond locate the same absolute time. Removing the last key or clearing keys retains the current sampled pose; reset explicitly restores defaults. `shared/easing.mjs` owns stable normalized `keyProgressAt` and `keyProgressPolynomial` facts for retained phases. Numeric preview, interpolation graphs, audio automation and dynamic picture export consume them; factoring out phase width avoids cancellation/underflow at legal tiny intervals. Normal-frame and held-edge picture sampling agree on this owner; full-range entry/exit animations keep their existing full-phase easing.
- `adjustments`: `{brightness:1,contrast:1,saturation:1}`, each 0–2. These are CSS-style sRGB multipliers applied in that order. Export uses RGB channel transfer and the CSS saturation matrix, with channel-range clamping between stages. These are this editor's defined controls, not a numerical reproduction of Jianying's proprietary adjustment algorithms.
- `volume`, `muted`, `audioDetached`: `shared/audio.mjs` owns linear gain 0–2 (default 1), clip mute (default false) and the video-only detached-source flag (default false). Mute retains gain/fades; a detached video no longer emits original audio. `clipAudioEnabled` also consumes project lane routing in addition to media audio, clip mute and detached-source suppression. Gain is canonical; dB is the reversible display/edit conversion `20*log10(gain)`, with zero shown as −∞. The finite UI input normally starts at −60dB, retains an already quieter positive gain, and is capped at `20*log10(2)` ≈ +6.0206dB. The slider remains 0–200%. Invalid explicit booleans/null/gain are rejected. `detachClipAudio` returns one project edit: it marks the video and creates an independent audio clip referencing the same media, exact constant/segment/curve timing, gain/mute/fades, pan/effects/volume keys and a selected target audio lane (default 0), without picture fields. It does not alter the media bytes or keep a linked edit group. Whole-project validation precedes the one Undo entry.
- `audioGainKeys`: `[{id,time,gain,easing,phase}]`, default empty. Time is clip-local seconds in [0,duration], strictly increasing by at least .000001s; IDs are unique within the clip, gain is a 0–2 multiplier, easing is linear/easeIn/easeOut/easeInOut, phase defaults [0,1] and must be a strictly increasing pair in [0,1]. `MAX_AUDIO_GAIN_KEYS=128` is a project-wide total separate from 128 transform keys and 128 speed nodes. Before/after keys hold endpoints; no keys means multiplier 1. Total pre-limiter scalar gain is base volume × key multiplier × fades, with a possible single-clip maximum 4 before mixing. Deleting the last key restores multiplier 1 without changing base volume. Move retains local key time; trim/split insert only necessary sampled boundary keys and retain the original easing subphase; retime scales times with duration. `audioGainMultiplierAt`, mutation helpers and `audioGainPlan` own these facts. The renderer selects normalized cubic intervals with a balanced tree, O(log keys) per sample, rather than reinterpreting names/phases or scanning every key.
- `pan`: −1..1, default 0; independent linear stereo balance, not equal-power mono panning. p≥0 multiplies left by 1−p, p<0 multiplies right by 1+p, the other source channel is unchanged. Center does not attenuate either channel. This does not claim equivalence to Jianying's observed −50 setting (roughly 2.4 left/right amplitude ratio in this reference).
- `audioEffects`: defaults `highpass:{enabled:false,frequency:80}`, `lowpass:{enabled:false,frequency:12000}`, `echo:{enabled:false,delay:.2,decay:.3}`. HP/LP are 2-pole Q=1/√2, frequencies 20–20000Hz; echo is dry unity plus one delayed tap, delay .01–1s and decay 0–.8, with no feedback. Disabled parameters are still retained and validated. `AUDIO_EFFECT_LIMITS` and `clipAudioEffects` own parsed facts. Order: source-clock conversion → 48k stereo → HP → LP → echo → stereo balance → base×key gain → fades → clip-tail trim → timeline placement → mix → limiter. Echo cannot extend clip/project length. Each clip owns independent filter/echo state; split does not promise to inherit pre-split IIR or delay history.
- `fadeIn`/`fadeOut` and `fadeInCurve`/`fadeOutCurve`: timeline-second gain envelopes, including video source audio. Each duration is 0–clip.duration and their sum cannot exceed it. Shapes default to linear; valid IDs are linear (u), easeIn (u²), easeOut (1−(1−u)²), equalPower (sin(πu/2)), with clamped progress. Fade-out evaluates the selected function at remaining fade fraction. They run after source trim/speed conversion and before timeline placement. `audioGainAt(clip, absoluteTimelineTime, project)` includes base/key gain, both fade shapes and clip/project routing, and is zero outside the half-open clip interval. Desktop realtime audio and Node offline export execute shared/audio-dsp.mjs on the same prepared48kHz stereo Float32 source-clock PCM. Base/key gain may exceed1 before the final shared limiter. Source/speed edits prepare PCM asynchronously; gain/pan/routing/key edits do not re-stretch PCM, while filter/echo changes warm their state before applying. Browser-only editing without the desktop bridge explicitly lacks realtime audio; generated WAV/MP4 remain available with the local media service. Splitting keeps original outer fade-in only on the first piece and outer fade-out only on the second, clamped to retained duration; no repeated inner fade is inserted.
- `animation`: `{in:0,out:0,inType:'fade',outType:'fade',easing:'linear'}`; video/image-only timeline durations, each 0–clip.duration and sum <= clip.duration. Twelve types are fade/slideLeft/slideRight/zoom/slideUp/slideDown/rotate/pop/zoomFade/rotateFade/spinZoom/swingFade, easing linear/easeInOut/easeIn/easeOut with the same progress definitions as keys. fade changes alpha; slideLeft entry adds −project.width→0 to x and exit adds 0→−project.width, with slideRight opposite. zoom multiplies scale by .5→1 on entry and 1→.5 on exit. slideUp adds −project.height→0 on entry and reverses on exit; slideDown is opposite. rotate adds −90°→0 on entry and 0→−90° on exit. pop multiplies scale by `.5+.5*(1+2.70158*(p-1)^3+1.70158*(p-1)^2)`, where p is eased entry progress (reversed for exit): .5→approximately1.05→1. zoomFade combines the same .5→1 scale with 0→1 alpha; rotateFade combines −90°→0 rotation with 0→1 alpha, both reversed for exit. spinZoom adds −180+180p degrees, multiplies scale by .1+.9p and alpha by p; swingFade adds 20*sin(6πp)*(1−p) degrees and alpha p, without scaling. Here p is the existing eased entry progress or reversed exit progress. `shared/effects.mjs` owns the catalog, numeric sampling and FFmpeg expression coefficients; UI and validators consume that owner. `pictureTransformAt(clip, absoluteTime, project)` combines key pose with preset geometry and key opacity; multiply `animationAlphaAt` separately for fade alpha. UI names entry/exit directions explicitly; they do not imply equivalence to Jianying's preset naming. Audio is unaffected. Trim/split retain only original outer animations not cut away and clamp them to the remaining duration.
- `mask`: `{type:'none',x:0,y:0,width:1,height:1,rotation:0,feather:0,invert:false}`; types `none`, `ellipse`, `rectangle`. Center x/y are project-normalized offsets (-2–2), width/height are project-normalized sizes (.01–4), and clockwise rotation is -360–360 degrees. UI displays position in project pixels and size in percent. The shape operates on the fitted project canvas before the overall clip transform and multiplies existing source alpha. Feather 0–200 project pixels means Gaussian sigma=feather/3; inversion happens after blur. `maskGeometry` owns conversion to project geometry and outside-canvas padding. Export builds a bounded monochrome mask, blurs it once with FFmpeg gblur (three steps), crops and reuses it. Preview uses an SVG Gaussian mask. These two rasterizers can differ at edges; no identical kernel or subpixel equivalence claim is made.
- `transitionOut`: `{type:'none',duration:0}` or `{type:'dissolve'|'wipeLeft'|'wipeRight'|'fadeBlack'|'wipeUp'|'wipeDown'|'circleOpen'|'circleClose'|'pushLeft'|'pushRight'|'slideLeft'|'slideRight'|'fadeWhite'|'splitOpen'|'splitClose'|'boxOpen',duration,nextClipId}`; the outgoing video clip owns a transition to the named, still-adjacent next clip on the same layer (cut tolerance .001s). Duration is .04–5 seconds; each half must fit its side's clip, and a clip's incoming/outgoing half-windows cannot overlap. The window is centered on the unchanged cut. Original source timing continues inside each clip; outside the clip interval its first/last picture frame is always cloned, even when unused source handles exist. Audio is neither extended, shifted nor crossfaded. Each picture is masked/transformed/animated before edge cloning. dissolve linearly mixes premultiplied RGBA; wipeLeft reveals the next picture from right to left, wipeRight from left to right, using a project-normalized clipRect outside the overall transform. wipeUp reveals from bottom to top; wipeDown from top to bottom. circleOpen reveals incoming inside a center circle whose radius grows 0→center-to-corner distance; circleClose reveals incoming outside the circle while that radius shrinks 1→0. The project-normalized clipCircle also acts outside the clip transform. Browser hard-stop radial masks and FFmpeg binary-circle sampling share geometry but need not have identical subpixel edges. `shared/effects.mjs` owns these geometry/blend definitions. fadeBlack fades the first picture to opaque black then reveals the next; blackOpacity joins the samples by premultiplied plus-lighter addition, not a source-over darkening overlay. fadeWhite uses the same two half-window weights but adds opaque white on all RGBA channels, so its midpoint is opaque white including otherwise transparent regions. pushLeft/right translate both completed picture canvases in the named direction by a full project width; slideLeft/right keep the outgoing canvas stationary and translate only the incoming one. The incoming footprint replaces the outgoing sample, including its alpha, so transparent incoming holes reveal lower project layers rather than duplicate the outgoing picture. splitOpen reveals incoming within a centered vertical strip of width p; splitClose retains outgoing inside width 1−p and reveals incoming in its complement; boxOpen reveals incoming inside a centered rectangle whose width/height are p of the project canvas. These three windows replace full RGBA samples in complementary regions; p=0/1 preserves exact endpoints under pixel-center sampling. `clipRect.outside` is the owner fact for a rectangle complement, expressed by an evenodd polygon in preview and a fixed-canvas blend in export. `transitionSampleStyle` owns preview translation and clipping; `transitionRenderFilters` returns outgoing/incoming filters and a complete two-input combineFilter from a caller-owned clock function (t for spatial crop, T for blend). `shared/transition-motion.mjs` owns the fixed 2W push and 3W slide canvases; no full-frame GEQ displacement is used. The composed layer retains lower layers at transparent endpoints, while black/white midpoint coverage is opaque. Browser fractional translation and integer export crop can differ at subpixel edges. These independent effects do not implement Jianying's observed motion blur. `inspectTransitions`, `maxTransitionDuration`, `visualLayersAt` and `reconcileTransitions` own these rules. Reconciliation is pure and removes invalid owners after client edits; the API rejects invalid transition input rather than repairing it. Splitting keeps outgoing ownership only on the right fragment; changing its pair identity removes the transition.

`clipTiming` owns derived source/timeline spans with mode constant/segments/curve; `sourceTimeAt` and `sourceRateAt` accept absolute timeline seconds, and `timelineTimeAtSource` provides inverse mapping. For a curve, clipTiming.segments contains one decoder span with the full sourceDuration and integrated output duration; it is not a constant-rate editing representation. `changeClipTiming` and `trimClip` are pure edit boundaries: moving start does not reinterpret source or local keys; ordinary speed changes preserve the source interval and clear segments/curve; segment changes clear curve and recompute duration; curve changes clear segments and integrate the retained source span. Clearing curve chooses ordinary 1×. Retiming scales key times with the new clip duration. Trim/split slice source spans and retain eased key and speed subcurves. Source overflow is cropped using the inverse mapping. Ordinary speed is bounded so a retained short source interval still produces at least .04s; a segmented or curve total shorter than .04s is rejected with a useful error. Frontend capacity guards reject edits before committing, and the API independently validates all limits.

Curve support remains bounded by the analytical maximum source-domain rate derivative, `MAX_SPEED_CURVE_SOURCE_SLOPE=8` speed units/source second, including retained phase. This is the locally verified support domain, not a dynamic-atempo safety threshold. Mutations/API use `assertSpeedCurveSupported`; over-steep edits reject atomically. The 900-second project, 3600-second retained curve source span and 128 total curve nodes remain independent bounds. Picture timing remains continuous.

**Nonflat curve audio retains the continuous engine introduced in 0.8: it uses one continuous offline Rubber Band 4.0.0 R3 + WindowShort stretcher for the entire selected source interval.** `curveAudioPlan` owns engine identity `rubberband-4.0.0-r3-short-offline-v1`, exact `round(duration*48000)` output frames, `round(sourceDuration*48000)` source frames, and the source/output sample map. Every 960 source frames (20ms), the owner integrates the same retained smoothstep/phase curve and rounds its output sample position. `curveAudioTimeMapBatch` serializes at most 4096 map entries per call; it is a map serialization boundary, not independently restarted audio processing. The native helper bounds the whole map to 180000 entries, studies the selected source once, then processes it through that same stretcher using 256-frame input calls and bounded 4096-frame PCM buffers, with stereo channels together and pitchScale=1. Flat curves use the ordinary constant-speed chain; exact rate 1 uses anull, avoiding unnecessary atempo/WSOLA startup and fractional-tail loss. The former 75ms audio chunks/crossfades, 128-audio-block batches and block-count APIs are removed, not optional alternative algorithms. The independent 900-second project, 3600-second source, 128-node and slope-8 limits still apply.

For each nonflat clip the queue decodes the selected first audio stream once into 48kHz stereo float32 PCM, writes the sample map, supervises the offline helper, verifies its completion protocol and exact source/output byte counts, removes source PCM/map, and wraps output into a float WAV with 64KiB copying. The original selected source phase, including trim/split phase, comes from the shared owner; no consumer resets the subcurve at an edit. The export job owns decode/stretch/append/mux and cleanup, cancellation between children and during finalization, and close retry after cleanup failure. A missing helper, bad/nonmonotonic map, timeout, insufficient space or incomplete output fails explicitly; a partial output is never served as completed.

Before each preprocessing step, actual free space must cover `max(sourcePCMBytes+targetPCMBytes, 2*targetPCMBytes) + mapCount*24 + 16MiB`. Prepared WAVs from earlier clips and final mux still consume disk; this check is not an unlimited or zero-disk guarantee. Only one supervised media/helper child runs in the render queue at a time. The native map is bounded but grows with the retained source interval; batching its serialization does not make total map storage constant. A 3600-second source PCM is 1,382,400,000 bytes; a 900-second intermediate float WAV is 345,600,044 bytes. RAM/CPU/time measurements and the fixed-domain signal checks belong to the [0.8 backend report](artifacts/v08-20261018/BACKEND-CONTRACT-AND-VALIDATION.md), not these size estimates.

Exact target length and ideal map interpolation error do not promise sample-exact transient placement or perfect pitch for arbitrary audio. The historical 0.7 75ms-block implementation observed 440→445.31Hz (+1.21%) in one 60-second diagnostic and failed an earlier ±5Hz check; that remains historical evidence in [the 0.7 report](artifacts/v07-20261018/BACKEND-CONTRACT-AND-VALIDATION.md), not the current engine's default error. The retained 0.8 pitch criteria were frozen independently before baseline/current comparisons, including steady tone frequencies, transition markers, tails and stereo. The short map's `idealTimeErrorBound` bounds map interpolation only, not DSP transient placement. [Historical 0.8 native mixed-output validation](artifacts/v08-20261018/final-native-analysis/RESULT.md) separately checked that release’s actual MP4/WAV against its bound project/probes; it does not turn those finite checks into a universal pitch or perceptual guarantee.

`clipAudioSampleRange(clip,48000)` owns audio placement on the global half-open sample grid `[ceil(start*48000),ceil(end*48000))`, with only four-ULP normalization at exact integer boundaries, not millisecond quantization. Its offset drives local key sampling; segment sample counts, tail trim and sample-based delay share the same owner. Adjacent split ranges are disjoint and sum to the original count. The continuous curve helper’s rounded source/target PCM map remains a separate internal stretch boundary. At exact constant speed 1 the source is not run through atempo; this removes the observed fractional WSOLA flush gap instead of hiding lost samples with padding. Nonidentity constant speed and R3 stretch retain their existing discrete/DSP limits. [0.9 backend validation](artifacts/v09-20261019/BACKEND-CONTRACT-AND-VALIDATION.md) preserves the initial split/phase failures, strict thresholds, resource measurements, and cleanup/cancellation coverage.

`sourceTimesAt(clip,times)` is the batch form of the same source-clock owner; it preserves clamp/freshness semantics and validates a curve cache signature once per synchronous batch. Consumers such as waveforms use it rather than reimplementing integration or bypassing invalidation.

`shared/timeline-placement.mjs` owns media-to-track and clip-move placement. `resolveTimelinePlacement` accepts the project and `{mediaId|clipId,start,track?,layer?}`, returning either a parsed placement/duration/snap/unchanged result or an explicit failure. Four picture and four audio tracks are available; video/image and audio cannot cross track kinds, same-picture-layer collisions are rejected, and audio overlap is allowed. Timeline quantizes raw pointer time once, previews the owner result, and App revalidates the resolved placement with snapping off. A no-op move does not create history. Drop/move/start/layer edits never reorder other clips. A duration or speed edit may push only subsequent actually colliding clips on the edited picture layer, preserving full floating-point boundaries; unrelated tracks, keys and noncolliding positions remain unchanged. `src/clip-edits.mjs` owns this separate retiming consequence. The whole project remains bounded to 900 seconds.

Internal library dragging and existing timeline gestures share one Timeline pointer transaction owner. App delegates source-button pointerdown through `beginMediaGesture`; the source button may capture the pointer, while matching window-capture move/up/cancel events own continuation and completion. A real pointerup commits, Escape/pointercancel/actual window blur cancels, and a fresh pointerdown cancels any stale transaction. A move reporting buttons=0 never implies release. The owner consumes only the corresponding trailing mouse click after a moved/cancelled media gesture; keyboard/AX activation remains Add. Superseded internal HTML5 drag/MIME handling has been removed; external OS file drop stays an App import boundary. The speed-curve editor independently owns its window pointer lifecycle using fresh callbacks: a matching real up commits the latest legal draft once, while cancel/blur/Escape/lost capture restores the pre-drag state. Both owners remove listeners and release owned capture on unmount. Node-local capture is useful routing, not proof that a terminal event will reach that node.

Preview consumes the same picture owner samples and geometry. Only current video elements gate picture readiness; picture errors pause video with a per-source reload prompt. AudioContext/AudioWorklet live in a separate hidden renderer partition with a checked distinct OS renderer PID, independent startup/heartbeat watchdog, no media-element audio graph in the editor, and owned shutdown. Audio errors/buffering never enter the video gate. Saved projects start at0; only initial demo selection uses a16s presentation position. Audio uses transport epochs, DSP revisions and actual effective sample ACKs. Source changes halt before lease release; retry acquires a new prepare lease. Seek/filter changes use a2s bounded prefix and state snapshot, validated against a complete-head run under the fixed8e-5 sample criterion. This is a measured finite tolerance, not a mathematical infinite-IIR-history identity claim.

Export fits and composes on the project-size RGBA canvas, overlays video lanes in order, draws subtitles, then scales the completed canvas to the requested output width/height. A fixed-size affine warp (at most project width+2 by height+2) avoids allocating a 4× enlarged frame for zoom. Project duration, frame rate, 64-clip maximum, 64 original-source decode-input budget, 128 transform keys, 128 audio gain keys, 128 speed nodes, four video lanes and four audio lanes remain independent resource bounds. Prepared PCM inputs (up to 64) and monochrome mask inputs (up to 64) are additional: 64 is not a total FFmpeg-input count. Long 4K projects and worst-case combinations have not been stress-tested.

Normal picture coverage is the global output-frame interval `[ceil(start*fps),ceil(end*fps))`, with only a numerical tolerance at exact grid boundaries. `clipPictureFrameRange` owns this interval and the offset from the clip start to its first covered frame; curve and segmented decoders retain that source phase. Continuous preview controls are sampled at the current timeline time. Picture placement and transition padding use the output 1/fps time base with integer PTS N+startFrame; overlay coverage is evaluated as integer frame intervals. Never round frame/fps to six decimal seconds and convert it back: that may move the first incoming normal frame across a boundary and expose a one-frame black hole. This frame clock also prevents the bundled FFmpeg 4.4 tpad source/clone boundary from leaving a missing PTS and repeating the preceding blend at the cut. Output remains CFR with ceil(projectDuration*fps) frames, allowing numerical tolerance at exact frame boundaries. `clipPictureEdges(clip, project.fps)` owns edge snapshots on the global project frame grid: the first grid time at/after clip.start and the last grid time before its end; a subframe clip with no covered grid frame falls back to clip.start. Both preview and render retain those project-clock samples independently of the chosen output frame rate. Export takes the held tail from the same decoded source on a separate project-clock branch, processes only that picture through its mask and the shared sampled key/preset pose and animation alpha, and repeats it on the output clock. Inside original clip intervals export sampling follows output fps. These are independent editor semantics, not a reconstruction of Jianying's private speed, blend, animation or mask algorithms.

Subtitle: `{id,text,start,duration,fontSize,color,position:'bottom'|'center'|'top',outlineWidth,outlineColor}`. Font size and outline width are project pixels; colors use #RRGGBB. Outline width is 0–32 and defaults to max(1,fontSize/24), outline color defaults to #000000. Use a CJK-capable system font and preserve arbitrary text as literal data, never shell/filter code. Persisted subtitle duration is at least 0.04 seconds.

SRT import/export is local renderer text processing through `shared/srt.mjs`, with no network API. Parser supports UTF-8 BOM, CRLF, optional sequence numbers, multiline literal text, comma/dot milliseconds and overlapping cues; unrecognized or malformed blocks reject the entire file with cue/line context. The editor adds cues atomically only if the complete result fits remaining limits (120 cues, 30,000 total characters, 2,000 per cue, 900-second end time and 1 MiB file size); cues shorter than 40 ms are rejected before editing. Export sorts stably and writes millisecond timing with literal text; blank text lines that cannot roundtrip through SRT are rejected. SRT does not preserve fonts, colors, positions or outlines.

## 1.0 audio ownership and diagnostics

The limiter uses a240-input-frame peak window,239-frame output delay, threshold.95, instant gain reduction and50ms exponential release. Target gain is1/max(.95, recent stereo peak); output is bounded to[-1,1]. Low-level239-sample delay and1/.95 gain retain the previous contract; high-level limiting is an explicit1.0 change and does not claim old FFmpeg nonlinear waveform equivalence. This is not a loudness normalization or speaker calibration.

Source PCM cache identity includes source digest, engine digests and complete normalized source/sample clock; it excludes DSP/UI fields. Preparation and exports share the same owned queue, at most3 queued/rendering jobs, one media child. Asset reads require a live lease and accept at most16384frames. Up to4 idle leases expire after10minutes. Unleased cache limits are512MiB/128 assets, with owned orphan publication cleanup. Leased assets are additional:64×900s stereo Float32 can occupy22.12GB; free-space checks and explicit failure remain necessary. The live producer and Worklet share one stream contract:8192-frame blocks,4-block lookahead and at most8 retained blocks per input; first PCM is published with the install, and pending demand survives an active read. Node mixes4096-frame blocks. No complete project PCM is loaded into the browser.

User transport intent owns seeking. Only an explicit seek or source install changes the audio epoch; Play/Pause, monitor mute, video readiness and delayed observations do not infer a seek from frame differences. Healthy or buffering audio owns the preview playhead; explicit audio failure permits picture fallback. The preview endpoint consumes the shared project-frame-rounded audio clock, including a partial final quantum. Last-quantum capture completion occurs in that quantum, so an immediate pause cannot lose the completion event. Picture sampling clamps to the last project-frame start in the final padding interval. These rules fix the two rejected native candidates; they are not a promise of zero stalls on every device.

“录制实时混音” taps the actual Worklet final mix for at most30s of playing samples. Pause adds no samples; seek ends the current capture. Requests before a ready DSP state fail explicitly. A saved Float32 WAV has a JSON sidecar with first global frame, frame count, epochs/revisions/effective frames, asset identity and capture SHA. It is digital output before the device; it cannot prove physical speaker response.
